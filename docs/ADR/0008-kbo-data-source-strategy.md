# ADR 0008. KBO 데이터 소스 전략

- 날짜: 2026-09-13
- 상태: **확정** (2026-09-13 사용자 결정)

## 맥락
KBO 공식 기록실과 STATIZ 는 자동 수집을 금지한다 (etl/kbo/README.md 1절). 조사 결과 두 경로가 확인되었다.
- 야구나라가 기자·세이버메트리션 대상 맞춤 데이터 요청 창구를 운영한다 (정식 경로).
- 네이버 스포츠 API 가 2010~2026 시즌별 선수 기록을 반환한다. 다만 네이버 이용약관의 포괄 조항과 충돌하는 회색지대이고, SF·SH·IBB·BF 가 없다.
장기적으로 웹서비스 공개를 고려하므로, 공개 서비스에 쓸 데이터는 권리가 확보된 것만 허용해야 한다.

## 결정
1. **KBO 선수·팀 기록의 1차 소스는 야구나라 데이터 요청으로 받는 파일이다.** 요청 초안은 docs/data_request_drafts.md. 요청 시 협업 가능성도 함께 언급한다.
2. **KBO 사전 승인 요청도 병행 발송한다.** 승인되면 공식 기록실이 검증·보완 소스가 된다.
3. **네이버 API 백필은 사용하지 않는다.** 회신이 장기간 없을 때 임시 연구 데이터로 재검토할 수 있으나, 그 경우에도 `source='naver'` 로 표기하고 공개·학습 데이터 공개에는 쓰지 않는다.
4. **공식 사이트 크롤링은 하지 않는다.** STATIZ 는 수동 대조에만 쓴다.
5. **모든 사실 테이블에 `source` 컬럼을 둔다** (스키마 v1.1, W3). 소스가 바뀌어도 스키마는 유지한다.
6. **공개 서비스 규칙:** 권리 미확보 데이터는 비공개. 야구나라 데이터의 이용 범위(재배포, 학습)는 회신 시 서면으로 확인한다.

## 결과
- 데이터 도착 전까지 P1 은 MLB(Lahman) 검증으로 진행하고, KBO 적재는 `etl/yagoonara/` 로더로 도착 즉시 수행한다. 로더는 컬럼 매핑 YAML 만 채우면 되도록 미리 만든다.
- 회신이 W4 까지 없으면 KBO 관련 게이트를 2주 뒤로 미루고, 그 사이 MLB 로 예측 모델(P2)을 먼저 개발한다.
- 웹서비스 단계의 데이터 권리 경로는 docs/web_service_roadmap.md 에 따른다.
