# ADR 0008. KBO 데이터 소스 전략

- 날짜: 2026-09-13
- 상태: **제안** (사용자 결정 대기)

## 맥락
KBO 공식 기록실과 STATIZ 는 자동 수집을 금지한다 (etl/kbo/README.md 1절). 조사 결과 두 경로가 확인되었다.
- 야구나라가 기자·세이버메트리션 대상 맞춤 데이터 요청 창구를 운영한다 (정식 경로).
- 네이버 스포츠 API 가 2010~2026 시즌별 선수 기록을 반환한다. 다만 네이버 이용약관의 포괄 조항("이용자의 실제 이용을 전제로 하는 제공 취지에 부합하지 않는 자동화 이용 금지")과 충돌하는 회색지대이고, SF·SH·IBB·BF 가 없다.
장기적으로 웹서비스 공개를 고려하므로, 공개 서비스에 쓸 데이터는 권리가 확보된 것만 허용해야 한다.

## 제안
1. **정식 경로를 오늘 시작한다.** 야구나라 데이터 요청과 KBO 승인 요청을 발송한다 (docs/data_request_drafts.md). 야구나라에는 협업 가능성도 함께 언급한다.
2. **회신 대기 중 임시 데이터는 사용자 판단에 맡긴다.** 네이버 API 저속 1회 백필(약 340 요청, 2초 간격, 캐시)을 연구용으로만 쓰는 선택지 B. 이 데이터는 `source='naver'` 로 표기하고 공개 서비스와 학습 데이터 공개에는 쓰지 않는다. 사용자가 거부하면 회신까지 MLB 로 진행한다.
3. **공식 사이트 크롤링은 하지 않는다.** STATIZ 는 수동 대조에만 쓴다.
4. **모든 사실 테이블에 `source` 컬럼을 둔다.** 소스가 바뀌어도 스키마는 유지한다.
5. **공개 서비스 규칙:** 권리 미확보 데이터는 비공개. 이 규칙은 웹서비스 로드맵(docs/web_service_roadmap.md)의 전제다.

## 결과
- 야구나라 회신이 오면 그 데이터가 1차 소스가 된다. SF/SH/IBB 포함 완전한 기록으로 지표 재현 정확도가 올라간다.
- 네이버 백필을 쓰는 경우 PA·SF·BF 는 근사값이며 데이터 사전에 그렇게 기록한다.
- P1 일정: 회신 대기와 무관하게 W3 MLB 검증은 진행. KBO 적재는 데이터 도착 시점에 W4~W5 로.
