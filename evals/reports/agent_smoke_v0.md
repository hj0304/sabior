# 에이전트 스모크 평가 v0 (P3 골격, 2026-09-25)

- 모델: 조건 B = 로컬 `qwen3:4b-instruct` (Ollama, Q4), 파인튜닝 전 베이스 + 도구
- 조건 A (프론티어 API)는 ANTHROPIC_API_KEY 가 없어 미실행. 어댑터는 구현돼 있다 (`agent/adapters.py`)
- 문항: `evals/benchmark/smoke_v0.jsonl` 12개 (조회 4, 예측 2, FA 2, 환각 함정 4). 원자료: `smoke_qwen3-4b_prompt_v1*.json`
- 재현: `uv run python -m evals.run_smoke --model ollama:qwen3:4b-instruct`

## 구조

| 구성 | 파일 | 내용 |
|---|---|---|
| 도구 11개 | `agent/tools/stats_tools.py`, `model_tools.py` | 선수 검색, 시즌 타격·투구, wRC+ 리더보드, 리그 상수, 팀 시즌, 선수 예측(구간), 팀 예측, FA 금액 추정, FA 계약 조회, 규정 조회 |
| 응답 봉투 | `agent/tools/base.py` | `{ok, as_of, data, sources, warnings}` / `{ok:false, error:not_found}`. 잘못된 인자·없는 도구도 예외 대신 봉투로 |
| 어댑터 | `agent/adapters.py` | Ollama, Anthropic, Scripted(테스트) |
| 루프 | `agent/runner.py` | 최대 6단계, **as_of 가드**(기준일을 모든 도구 호출에 강제 주입), JSONL 로그 `data/agent_logs/` |
| 근거 추적 채점 | `evals/graders/trace_check.py` | 답변 숫자가 도구 결과·인자·질문에 있는지. 반올림·% 변환 허용, 날짜 제외 |
| HTTP | `app/api/main.py` | 같은 도구를 `POST /v1/tools/{name}`, 에이전트를 `POST /v1/ask` 로 노출 |

## 약점 목록 (P4 파인튜닝 대상)

| 유형 | 문항 | 관찰 | 프롬프트로 고쳐졌나 |
|---|---|---|---|
| **도구 호출 날조** | S11 | get_rule 을 부르지 않고 "근거: get_rule(FA_COMPENSATION, 2025)" 라고 쓰고 보호 명단 "3명" 을 지어냄 | 아니오. v1.1 에서도 같은 근거 줄만 출력 |
| **도구 없이 답함** | S03 | 스쿠발 2024 기록을 조회하지 않고 일반론. ERA 를 "Expected Run Average" 로 잘못 정의 | 아니오 |
| **검색 실패 후 재시도 안 함** | S05, (S01 v1) | "후안 소토" 한글 검색 실패 → 영문 재검색 없이 "없는 선수". v1.1 에서는 league=KBO 로 검색 | 부분. 저지는 v1.1 에서 성공, 소토는 실패 |
| **결과 옮기기 오류** | S02 | 수치는 정확하나 MLB_LAN 을 "다이아몬드백스" 로, Judge 를 "아론 제이지" 로 옮김. wRC+ 213.9 를 "평균보다 50% 더" 로 해석 | 부분 |

이 목록이 SFT 데이터 설계의 출발점이다.
- 도구 호출 날조·도구 없이 답함 → SFT 에서 "모든 수치 질문은 도구 호출로 시작" 패턴, DPO 에서 날조 답변을 rejected 로.
- 재시도 → 실패 후 영문·성만으로 다시 찾는 멀티턴 예시.
- 옮기기 오류 → 팀 ID·선수 영문명 대응표를 도구 결과에 넣는 것(도구 개선)과 해석 문장 예시(SFT)를 함께.

## 도구 쪽 개선 (바로 할 수 있는 것)

- search_player 결과·다른 도구 결과에 팀 이름(한글)을 함께 넣는다. 모델이 ID 를 번역하다 틀리는 문제를 줄인다.
- 한글 MLB 선수명 → 영문 매핑 사전(주요 선수 수백 명)을 search_player 에 붙인다.
- wRC+ 등 지표에 `interpretation` 필드(예: "리그 평균 대비 +114%")를 넣어 해석 오류를 줄인다.
